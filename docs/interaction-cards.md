# 按钮与单条工单进度

只@机器人或发送“菜单”显示按钮。排班：今明、今天、明天、可休、身份、指令说明；工单：待办、继续、清理预览、状态、指令说明。身份设置、补充与填/完仍使用原短口令。私聊菜单不再自动额外查询排班/首页；首页和查询短词仍有效。

按钮限创建者在原群/私聊使用，点击时重新检查授权；普通菜单1小时有效，最多保留100张未过期卡。事件msgid持久化排重，先回应事件再执行原路由。清除按钮5分钟有效且单次使用，绑定服务端原清单摘要；旧卡不能确认新清单。保留按钮仅撤本次确认。完整清单超112字时继续文字确认，不截断范围。明确卡片拒绝可回退文字；回执不明不自动重发业务，原短口令始终可用。

普通工单在同一streamId显示识别、实际飞书核对及原最终回执，排队也复用该ID且等待排队回执，进度串行发送，结束后不再被计时器覆盖。worker stderr只发recognizing/checking白名单，stdout机器JSON不变。字段不清、未提交或需核验时保留原失败状态，不显示已登记。卡片查询先更新原菜单，结果主动回原会话，不把普通流式回复直接发给事件回调。

采用WecomTeam/aibot-node-sdk公开协议（MIT）：https://github.com/WecomTeam/aibot-node-sdk 。截至2026-11-03最近推送2026-04-07；适配现有连接、状态和权限，未安装或替换SDK/守护。飞书继续浏览器，不接API、不改变权限/查重/写入范围。没有新增模型调用、飞书或腾讯请求、依赖或固定费用；真实阶段增加少量既有企业微信连接发送，月流量未测。

验收仅模拟发送、合成状态及实际入口离线回放，不清真实任务、不新增在线记录或主动群发。群聊/私聊实际卡片显示与一次真实图片流仍待使用者验收；不据此宣称一分钟登记达标。

回调兼容：同时处理SDK示例的平铺event_key/task_id及实际event.template_card_event嵌套字段；两种字段冲突即拒绝。参考https://github.com/WecomTeam/aibot-node-sdk/issues/22 。按官方接收顺序区分callback与无cmd的ACK，避免共用req_id时吞掉事件。只记录按钮阶段和静态错误，不记录回调原文或账号。客户端成功提示不算查询成功，必须看到具体排班/待办并核对业务回调。

终态卡兼容：确认/保留后保持合法的button_interaction结构，并提供原有只读“查看待办/查看排班”入口；已消费确认只允许查看，不再次执行确认。避免text_notice缺card_action导致平台42045错误。此修复不会重放先前失败的确认；须重新预览。

实际验收：两个机器人的按钮已返回具体查询内容，后台已核对事件及原查询通道；清理确认和后续待办查询也有实际业务回执。保留/过期/权限/重放等边界另以合成状态验证。真实图片状态流与一分钟完整登记仍待实单验收。
