# 新成员申请使用

适用于独立的排班与工单机器人。新成员先在目标群 @ 对应机器人发送 `我 本人姓名`，私聊也可发送；兼容原身份口令。姓名须唯一匹配该机器人的配置成员名单，群昵称不作为账号凭据。

机器人从实际消息获取账号和申请会话，仅保存申请所必需的姓名、账号、会话、编号与有效期到本机授权状态，不保存申请正文，不送入匿名统计。新申请一小时有效，最多20条；重复申请提示等待，未批准不能查询、下载图片或处理工单。两个机器人分别申请、分别批准。

维护者在对应机器人运行目录执行：

```powershell
node scripts/access-requests.cjs list
node scripts/access-requests.cjs approve <申请编号>
node scripts/access-requests.cjs reject <申请编号>
```

先通过本人或可信渠道核对列表中的实际账号、姓名、会话，再批准。申请编号不是发给其他人自行配对的码。没有可确认的申请，不凭群昵称或旧文件授权；拒绝不授予权限，过期后需本人重发。已处理申请不能重复批准；跨账号同名或已有身份冲突需维护者核对，不覆盖原绑定。固定白名单启用时不绕过白名单扩权。

批准授予该账号当前机器人的业务使用权，并绑定申请所在会话。工单机器人下一条消息会把已批准的姓名写入对应的工单会话；不覆盖冲突身份、不读取或转移别人的任务。其他群与私聊继续遵循各自的身份确认规则。批准后本人重新 @ 机器人发“菜单”。排班可发“今”，工单可发“单”验证，只读验证不需发工单图片。

本机维护接口仅监听原127.0.0.1端口，拒绝浏览器来源及非法Host，使用本机凭证鉴权；维护脚本在本机读取凭证，不在命令参数或输出显示。接口限制JSON大小和读取超时，不增加对外监听端口。群内管理指令仍被拒绝，授权不会改变源表写入边界。

成本：申请、批准、绑定均在本机执行，不调用模型，不新增服务器或月费；仅占少量现有磁盘和企业微信消息流量，具体按量消耗未实测。业务识别仍按既有模型用量计费或占用套餐额度。

参考：[OpenClaw pairing](https://github.com/openclaw/openclaw/blob/main/docs/channels/pairing.md)，MIT许可证，核对时仓库仍活跃。复用其先批准再使用、过期和数量限制思路；未引入框架或复制平台适配器。
