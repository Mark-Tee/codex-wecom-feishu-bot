# 业务查重与零写入安全验收

## 已确认规则

双方的事务单号和机房出入单号都齐全时，仅组合完全相同判重复；只有一个可核验号时按该号查重。相同事务单号、不同机房出入单号可作为不同业务任务。不得因字段缺失自动补写或修改已有飞书记录。查重匹配规则不放宽新工单原有的单号完整性校验：缺少必填单号仍停止自动建单，不猜测或补号。

## 实际 record 接入保护

默认 `feishuBrowser.orderDeduplication=true`，本机审计目录为当前数据目录下的 `feishu-order-guards`。首次运行必须先核验任务号、事务单号、机房出入单号的字段映射，以及覆盖全表的读取视图；缺失、不完整或分页变化时拒绝创建，不能通过猜测字段绕过查重。

添加记录之前和提交之前都做完整只读扫描，同时取得任务号序列，复用原来两次任务号扫描，不新增周期轮询或模型调用。当前页面的origin/base/table在每次填写和提交前核对，不能因为显示名称一样就向其他表写入。

本机持久化状态只保存业务单号哈希及提交阶段，不把明文单号、图片或凭证写入审计索引。每个目标表采用独占临时写锁，防止本机多个执行者同时建单。已提交、创建开始后失败、提交结果不明或进程中断的同单禁止自动重试；必须先只读核验真实结果。仅在明确尚未进入创建步骤且工单指纹完全相同时允许原待办重试。损坏的审计或遗留写锁不会被自动清除。

共享表历史重复单测试是例外：须独立本机单次许可显式含 `allowExistingOrder:true`，同时匹配完整任务指纹、目标、有效期，且为feishu-test模式和“【测试勿统计】”标记。只有标记、普通群指令或普通授权账号不能绕过。已消耗的许可仍不可复用。

## 本轮验收

新增17项安全回归：组合与单号规则、完整分页、分页失败/重复/变化/字段错误、跨进程并发、提交结果不明的持久阻断、安全阶段原待办重试、损坏状态拒绝、明确测试例外、错表、跨会话短号和未授权请求。

使用实际工作器及真实飞书数据做了只读命中验证。注入的会话只允许目标URL和GET扫描，任何添加记录、点击、填字段或其他界面脚本均拒绝；已有业务工单在进入创建步骤之前被拦截。前后完整字段快照一致，新增/修改/删除为零。证据留本机，不公开业务数据。

## 边界与成本

本机锁不是云端唯一约束；其他电脑、手工操作或其他机器人在最终检查与提交之间仍可能竞争。本轮不擅自修改共享表结构，跨客户端并发的最终约束仍须隔离环境验证并另行决定。

本轮没有测试真实断网、重启Windows、完整角色正向流程或10次真实写入。提交结果不明采取停止并核验，不声称已经完成所有自动恢复。

门禁、哈希和安全回归不调用模型；重复图片在识别出单号前仍可能占用既有模型额度，不能把防重复写入说成完全免识别消耗。没有新增依赖、托管或固定费用；列表读表复用原有次数，实际代理流量仍未量测。
