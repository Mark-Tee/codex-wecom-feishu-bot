# 匿名使用统计与本机改进建议

排班、工单实例分别记录新收到的指令类别、次数、输入方式（按钮/文字/图片）、短口令/完整表达、群聊/私聊、结果与耗时。只汇总总体习惯，不建立个人画像，不新增远程管理命令。

数据落在各实例根目录 `logs/observability/events.log`；发生新事件后最多一分钟刷新 `report.md`。启动时也生成报告。事件日志单份最大1MiB、最多5份轮转归档，加当前文件共约6MiB/实例。报告只统计近30天、且仍保留在容量窗口中的事件；高频使用可能不足30天。原有诊断日志不导入、不清理，也不受这份采集脱敏声明替代。

新事件仅保存固定枚举、次数、毫秒耗时与精确到分钟的记录时间。禁止保存消息正文、图片、姓名、账号、群号、工单号、路径、链接、凭证、完整错误及堆栈。统计报表和事件日志都不提交Git、不上传任何外部服务。采集写入失败不打断业务，本机健康接口的 `observability.dropped` 会显示本次进程未能保存的次数。

## 结果含义与局限

- `handler_returned`、`worker_returned`仅说明代码返回，不能代表已建单或源数据正确。
- 只有飞书record模式、提交成功、字段检查通过、提交读回流程完成且不需后续读回，才记 `registration_verified`。表单模式、提交结果不明不计入登记成功样本。
- `draft_returned`仅表示草稿仓库函数返回，没有把它标成独立在线验收。
- 权限拒绝、需补充、单号格式、源冲突、写前保护、本机核验分别记录。浏览器未完成/保护拦截可能是查重等正常行为，不能自动归因程序故障。
- 耗时从本次消息收到开始，包含图片下载与排队；消息重放去重仍由原业务机制负责。补充指令是另一次请求，无法恢复跨多轮整单总耗时。进程中断中的请求只有接收事件，不伪造完成结果，也不自动重放。
- 匿名数据不能定位某个人、还原模糊原文或自动判断按钮意图。输入为图片/混合消息时只记类型，不读取图片内容来建画像。
- 建议按错误类别、识别补充频次、未分类指令与登记超过60秒等规则生成。少于20个耗时样本不报告P95。报告会列实际样本数量，不承诺一分钟登记目标已达成。

本地规则汇总不调用模型，不自动改代码、权限、排班、在线表或部署。维护者先审查建议、复现，再做最小修改与验证。

## 参考与成本

GitHub优先检索关键词：structured logging redaction、OpenTelemetry JavaScript metrics。参考 [Pino](https://github.com/pinojs/pino)（MIT，2026-10-06仍有更新）的结构化和字段脱敏做法，以及 [OpenTelemetry JS](https://github.com/open-telemetry/opentelemetry-js)（Apache-2.0，2026-11-01仍有更新）的结果/耗时分离。此实现复用项目已有日志轮转与Node标准库，没有引入上述依赖或采集服务，采用字段白名单比在完整报错中替换字符串更适合本次最小数据范围。

无新增固定月费、域名、托管、外部API或统计模型调用；占用现有本机磁盘与少量CPU。两个实例合计事件容量约12MiB，加两份小型报告。正常每分钟有变更才汇总，读取每实例最多约6MiB，日志写入按事件发生。该模块没有网络上传，因此不会额外产生机场统计上传流量；原机器人连接、图片识别与开发调试仍消耗既有资源/模型额度，未实测月度总流量和额度。无自动付费或购买。
