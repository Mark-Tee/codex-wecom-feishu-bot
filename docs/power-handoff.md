# 动力交班私聊草稿

排班机器人按已绑定的排班身份和最新在线排班，在动力白班当天16:30、动力夜班次日07:30，将模拟交班草稿主动私聊给当班动力人员。群内绑定也可用于找回相同账号的身份；同账号一致绑定只发送一份。账号必须已获排班机器人授权；身份或收件账号有冲突时不自动选择。

草稿保留原交班模板，并明确注明模拟、生成时刻和交班前复核要求。人员展示接下来的班次：动力人员单列，“在岗”为接班班次本站的非动力人员，排除异地和休假。统计刚结束前一班的本站任务，排除测试标记，按已确认业务单号规则去重；分类由本机明确映射，未知或冲突标待核对，不调用模型猜测。

## 使用

- `排班身份 姓名`：绑定本人准确姓名，例如`排班身份 测试甲`，需授权且唯一匹配名册。
- 提醒自动触发，无额外参数；只私聊当班动力人员，不自动发群或写在线表。
- `动力交班状态`：无参数，查看本人的提醒状态。例如直接发送`动力交班状态`。
- 收到后核对新增任务、分类、接班人员和实际交接状态，修改后再人工发群。16:30/07:30的数据不能代表17:30/08:30的最终情况。
- 读取失败一分钟退避，仅在预定时间后5分钟内重试；超出窗口、启用时已过时点均不补发旧稿。发送意图先落盘，发送结果不明、进程中断时不自动重发，需本机核验。
- 机器人依赖电脑在线、企业微信连接和已登录的正确飞书任务页。只读附着已有页面，不启动或切换浏览器，不填写任何表单。

## 本机配置

`roster.powerHandoff`：`enabled`、`enabledAt`（启用时刻ISO格式）、`workerConfigPath`（读取飞书只读配置）、`locationValue`（本站实际枚举）、`categoryRules`（明确的工作内容枚举及可选事项正则）。不把真实姓名、账号、业务记录或本机配置提交到公开仓库。

分类条目形如`{"workContentValue":"exampleWiring","category":"布线理线"}`；可选`descriptionPattern`用于区分上架/下架等明确事项。多条匹配也标待核对，不随意选一个。首次启用前须只读核验真实字段及枚举。

## 成本与验收边界

复用本地30秒定时器、现有企业微信长连接和浏览器登录；无新依赖、云服务或固定月费，不消耗模型Token。正常每天最多两个生成时段，未绑定当班人员时只核对排班，不读取飞书；发送前复查排班。只读分页、排班颜色核验、窗口内失败重试会增加网络和本机资源，实际月度流量、额度和电费未测量。

以约6150条主表记录、同月排班、每天两个班次均有唯一绑定为假设，每个任务约13次数据读取（排班前后各5次，飞书3页），每天约26次；本机CDP连接和已有保活另计。跨月和失败重试会增加次数，不能将请求次数直接换算成机场流量或金额。未接入新的付费API，也未核验现有平台全部计费或免费额度条件。

主动推送机制参考[企业微信官方SDK](https://github.com/WecomTeam/aibot-node-sdk)，复用项目现有发送及回执处理，不复制新第三方代码。离线测试及真实只读生成不等于真实私聊投递成功；需自然定时送达后由收件人确认。
